# Objections

This directory exists because criticism is part of the architecture.

Every serious objection should eventually have one of four outcomes:

- **open** — unresolved
- **testing** — being evaluated
- **accepted** — the criticism is valid and the model must change
- **resolved** — the model has been revised or evidence answered the objection

A useful objection should identify the claim under pressure, the evidence, and the consequence for the specification.

The project should become more credible by **showing its scars**, not hiding them.
